# Release 0.11 — External Reply Development Slice

## Purpose

Release 0.11 wires the provider-neutral Release 0.10 `THREAD_REPLY` core into the disabled-by-default synthetic external browser development path introduced in Release 0.9.

This is a **synthetic/local development slice only**. It is not a public production portal, production identity/session architecture, compliance claim, or customer deployment.

## Browser authority

The existing short-lived `sx_demo_external_capability` cookie remains transport only. It is not authorization truth and does not create a second authentication model.

The browser development adapter recognizes three independent AccessGrant operations:

- `THREAD_READ`
- `ATTACHMENT_READ`
- `THREAD_REPLY`

Every protected action re-enters the authoritative application layer with the server-held capability material. The adapter never widens a grant to simplify UI rendering.

A reply reaches `AccessGrantService.replyExternalConversation()`, which remains authoritative for bearer/verifier proof, deployment/thread scope, explicit `THREAD_REPLY`, revocation, server-time expiry, external-reply lifecycle, authoritative actor attribution, expected-thread-version concurrency, and the Release 0.10 `AccessGrantAuthorityGuard` at commit.

## Routes and UI

The existing external development namespace remains `/demo/external/access`.

Release 0.11 adds:

- `GET /demo/external/access/reply` — semantic server-rendered reply form after current reply-authority/lifecycle checks;
- `POST /demo/external/access/reply` — same-origin mutation boundary delegating to the Release 0.10 reply application service;
- `GET /demo/external/access/reply/sent` — fixed local Post/Redirect/Get confirmation target.

No bearer secret, capability value, verifier, or reply text is placed in a URL, redirect, analytics, or application log.

The session page displays only operations currently usable by the authoritative capability. UI visibility is convenience only; every POST independently revalidates authority.

## Same-origin and cookie boundary

Release 0.11 reuses the existing Release 0.9 mutation protection:

- browser Fetch Metadata accepts only `Sec-Fetch-Site: same-origin`;
- non-browser/in-memory callers without Fetch Metadata require strict Origin/Host/request-origin agreement;
- permissive CORS is not added.

The capability cookie remains host-only, `HttpOnly`, `SameSite=Strict`, path-scoped to `/demo/external/access`, ten-minute maximum age, and `Secure` when served over HTTPS. Cookie attributes are not weakened for reply.

## Reply semantics

A successful browser reply still creates only the Release 0.10 authoritative behavior:

- one immutable `EXTERNAL_TO_STAFF` bounded `PLAIN_TEXT` message;
- actor attribution from the AccessGrant `externalParticipantRef` only;
- authoritative `updatedAt`, `lastActivityAt`, and `attentionAt` advancement;
- minimized `MESSAGE_APPENDED` evidence;
- no automatic lifecycle transition.

Reply does not create or imply `THREAD_OPENED`, `ATTACHMENT_DOWNLOADED`, TransferAttestation, `THREAD_COMPLETED`, downstream filing, or per-user unread/read-receipt state.

## Feature gate

Release 0.11 intentionally reuses the two existing development gates rather than creating a second browser-authentication or reply-session switch:

- `SECURE_EXCHANGE_SYNTHETIC_DEMO=enabled`
- `DEMO_EXTERNAL_RETRIEVAL_ENABLED=enabled`

Both are required for the synthetic external-access namespace. Normal startup remains disabled.

## Validation boundary

Release 0.11 adds HTTP and real-browser coverage for reply-only/read-only operation independence, same-origin POST, safe PRG navigation, server-authoritative actor attribution, message validation, revocation/expiry/lifecycle denial, activity/attention behavior, and accessibility.

The Release 0.10 deterministic stale-thread, concurrent-revocation, and expiry-crossing regressions remain unchanged and continue to prove the application transaction boundary underneath the browser adapter.

## Deliberate non-goals

Release 0.11 adds no production public portal, customer data, PHI, production authentication/IdP, Cognito, SES/email delivery, notification links, public abuse/rate-limit infrastructure, AWS SDK, S3, DynamoDB, KMS, Lambda, API Gateway, infrastructure as code, external attachment upload, malware scanner, OCR, AI processing, analytics/tracking, frontend framework, or paid service.

Expected new recurring cost: **$0**.
