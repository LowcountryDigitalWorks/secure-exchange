## Hono request-source canary result

All three realistic Hono vulnerable canaries were missed by the verified default suite:

1. `context.req.param(...)` -> unsafe Hono HTML response — **NOT DETECTED**;
2. `context.req.raw.formData()` / `FormData.get(...)` -> unsafe Hono redirect — **NOT DETECTED**;
3. `context.req.param(...)` -> Node filesystem/path-sensitive read — **NOT DETECTED**.

The product conclusion is that meaningful built-in Hono request/source coverage was not demonstrated. The proof established a material request-source modeling limitation; it does not claim that every possible Hono sink is conclusively unmodeled.

## Model-isolation controls

Equivalent pure-Node controls executed with the same verified bundle and default suite were detected:

- `js/reflected-xss`;
- `js/server-side-unvalidated-url-redirection`;
- `js/path-injection`.

Those controls demonstrated that the relevant default queries and supported Node source/sink paths functioned, materially isolating the observed limitation to realistic Hono request/source modeling.

## Real product result

Pristine accepted Secure Exchange main produced **0 default-suite findings**.

That result is **not vulnerability-free assurance**. The proof demonstrated material missing coverage across the product's actual Hono request boundary, so a zero-finding result cannot be treated as comprehensive SAST coverage for Secure Exchange.

## Final product disposition

**B — PARTIAL / INSUFFICIENT FOR CURRENT ADOPTION**

**DEFER CODEQL FOR SECURE EXCHANGE.**

Do not enable or add as a consequence of this proof:

- CodeQL default setup;
- a non-blocking CodeQL pilot;
- a committed CodeQL workflow;
- security-extended;
- required CodeQL checks.

Do not change TypeScript or Hono for scanner compatibility, maintain custom Hono source models merely to force adoption, or automatically pivot to Semgrep/Opengrep.

## Reconsideration triggers

CodeQL may be reconsidered only when at least one accepted trigger applies:

1. official CodeQL adds meaningful built-in Hono request/response modeling;
2. Secure Exchange HTTP/source architecture materially changes;
3. Portfolio separately authorizes a justified centrally maintained framework-modeling evaluation.

Any future adoption still requires a new bounded product-specific proof against then-current protected main.
